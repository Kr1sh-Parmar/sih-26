# Data provenance and licences

**SIH PS 26188 — offline identity document screening.**

Slide deck source. Each `##` heading is one slide. Kept short deliberately:
`context/DEMO.md` requires the console to be legible from three metres and the
same applies here. The authoritative row-by-row record is `data/PROVENANCE.md`.

---

## Slide 1 — The one line

# Every document this system screens is synthetic.

Generated by `data/generator/` from **published layouts**, with
**checksum-valid** identity numbers — every Aadhaar, PAN, Voter ID and
passport number is *constructed* to pass the same Verhoeff and mod-11
functions Layer A validates it with. Not sampled and hoped over.

**No real Aadhaar, PAN, passport, Voter ID or driving licence image or
number exists in any fixture, any test, any demo document, or any commit
in this repository.**

Speaker note: this is a hard rule, and it is enforced rather than asserted.
Every dataset directory is gitignored, and no identity number is ever stored
raw anywhere — salted hash plus last four digits only.

## Slide 3 — Could this be deployed commercially?

**Honestly: yes, with one dataset to swap out.**

| Restriction | Where it sits |
|---|---|
| **LFW — research use only** | Face threshold *sanity check*. Not training data. Not in the shipped image. |

Replacing it is a re-run of one calibration script, not a code change — and
it is already the wrong dataset for our problem. LFW is live-to-live; ours is
document-to-live. The real operating threshold comes from our own consented
capture set, not from LFW.

**Nothing else we hold carries a non-commercial term.**

Two non-commercial datasets appear in our early planning document
(`context/DATA.md`) and are **not used**:

| Dataset | Licence | Status |
|---|---|---|
| DocXPand-25k | **CC BY-NC-SA 4.0** | **Not held.** Removed by the 2026-09-06 scope cut to Indian documents. |
| `passportdetection-rgnih/passport-fields-fio-photo` | **CC BY-NC-SA 4.0** | **Not held.** Never pulled. |

If a judge quotes either from an earlier version of our specification, that is
the answer: they were scoped out, and no NC-licensed bytes are on disk.

## Slide 4 — Biometrics and consent

**The only real biometric data anywhere in this project is our own team's
face images, for threshold calibration.**

- Held under **written consent**
- Stored **outside the repository**
- **Never committed**, and deleted after the event
- Used to calibrate exactly one number: the document-to-live cosine threshold

No passenger face. No third-party face. No scraped face.

The portraits printed on our demo documents are **StyleGAN / diffusion output
(SFHQ, CC0 public domain)** — no real person, so no consent question and no PII.

**The running system stores no face image.** Embeddings only, and the audit
trail carries no raw identity number — checked, not assumed.

## Slide 5 — ICAO Doc 9303: what we can and cannot claim

**Doc 9303 is a public international standard.** Our MRZ implementation is
written against it: the TD3 layout, the five per-field check digits and the
composite, and the supplementary nationality codes ISO 3166 does not define
(`D` for Germany, the `GB*` subtypes, `XXA` and `XXB` for stateless persons
and refugees).

**We do not hold the PDFs locally.** `icao.int` sits behind a Cloudflare
JavaScript challenge and returns **403 to any scripted fetch**; retrieving
parts 3 and 4 needs a human with a browser. This is recorded as outstanding
in `data/PROVENANCE.md`, not quietly omitted.

**Why that does not weaken the claim:** the standard publishes its own worked
examples, and our MRZ parser is tested against those specimen strings plus
deliberately corrupted check digits. If the implementation were wrong, those
tests would fail.

This is the one genuine external anchor in the system, and the one thing in
the pitch we did not build ourselves.

## Slide 6 — The caveat we volunteer before you ask

Our **field detector's training corpus** is public imagery from Roboflow
Universe, published by third parties under CC BY 4.0. Four of those sets
(`aadhaar-card-annotation`, `back-aadhaar-card`, `id-bdbwr`, `passport-ppwp8`)
appear to contain **real Indian cards** that their uploaders made public.

What that does and does not mean:

- It is **held locally, gitignored, and never redistributed by us**
- **Nothing real is committed**, screened, demonstrated, or in any fixture
- A trained detector retains **no image** — it learns where a field sits
- `data/PROVENANCE.md` flags this, and using those sets is recorded as an
  explicit owner decision rather than a silent default

Two further sets — `Aadhar dataset/Dataset 2` and a folder of synthetic
non-Indian passport renders — have **unrecorded provenance**. They are
reference material only and feed nothing.

We would rather say this than have you find it.

## Roboflow Universe (`data/raw/`, gitignored) — CC BY 4.0 unless noted

16 projects, ~6,691 images: Aadhaar (4 sets), driving licence (2), PAN (1),
passport (5), visa (1, **public domain**), document-type routing (2),
tampering (1). Pulled at build time with a private workspace key held in a
gitignored `.env`. **Roboflow is never called at inference.** Full per-project
list in `data/PROVENANCE.md`.

Note for the technically inclined judge: Roboflow's YOLO export is not
trustworthy. For one project the YOLOv11 export is corrupt — box heights
collapse to zero — while the COCO export of the same version is pixel-correct.
We always request COCO and convert locally, and check every pull by drawing
the boxes.

## Generated data (`data/generator/`)

| What | Source | Licence |
|---|---|---|
| Document images and labels | ours — labels are a by-product of drawing | ours |
| Identities | Faker `en_IN` + our own checksum functions | MIT |
| Portraits | SFHQ small-sample | CC0 |
| Fonts | Noto Sans, Noto Sans Devanagari, Noto Sans Mono | OFL-1.1 |
| Signatures | our own Ed25519 reference issuer | ours |
| Forgeries and masks | `data/tools/mutate.py`, five families | ours |

Templates are **drawn from published layouts, not traced from a specimen
scan**, and the State Emblem is deliberately a stand-in mark — the real one is
protected under the State Emblem of India (Prohibition of Improper Use) Act.

Our signatures are from a reference issuer we built. **We hold no government
key**, and the console renders a `disclosure` string on every verification so
a reference verification cannot be mistaken for a government one.

## Stated limitations of the generated set

- Portraits are not age- or sex-matched to the printed identity. SFHQ ships no
  metadata and we deploy no age model. They are consistent *across* one
  person's documents, which is what the cross-document and face checks need.
- The barcode is not a real symbology. Bars are derived from the value so the
  class has instances to locate; nothing decodes them and nothing claims to.
- The MRZ is set in Noto Sans Mono, not OCR-B, which is licensed. Glyph-height
  uniformity — what our conformance check actually measures — is identical;
  typeface identity is not tested and could not be.
- No print-and-rescan pass yet. These are clean renders, and a model trained
  only on clean renders degrades on a real scanner.
